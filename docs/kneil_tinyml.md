# kneil_tinyml: on-device activity classifier and daily mobility metrics (v1.1, model V3)

C99 library, no dynamic memory, single-threaded per instance. It classifies a **2 s accelerometer window every
1 s** into 9 classes and can add each result to a daily summary (34 bytes) meant to be sent over BLE instead of
raw data. In this repository it is used by the KNEIL live firmware (`src/kneil_live.c`).

Classes: 0 walking, 1 stairs up, 2 stairs down, 3 sitting, 4 standing, 5 lying, 6 sit-to-stand,
7 stand-to-sit, 8 bed transfer (rolling, sit-up at bed edge, lie-down).

Input: one sample at a time, in g, device frame **x anterior, y subject's left, z superior** (upright standing
gives about (0, 0, +1 g)), at **50 Hz** (the rate the model was trained for).

## Model V3 (16 Nov 2026)
Folder `KNEIL_results/tinyml_final_v3_lp6` of the training project (not in this repository). Forest of 20 trees
(18,900 nodes, about 192 KB of flash on the nRF54L15) plus a single small tree (1,117 nodes); 20 features,
9 classes; trained on 50 Hz data filtered by a 6 Hz low-pass, which the library applies on the chip.

Training data: simulated implant-site data (60 synthetic patients, 22 Camargo subjects replayed in the KNEIL
model), Caicedo older adults (virtual implant from markers), and real implant-site data of 265 people computed from
shank IMUs or motion suits (WearGait-PD, CeTI, PAMAP2, MHEALTH, KneE-PAD, Marpino; about 64 h).
Validation: 5-fold cross-validation **by person**.

| Walking recognised | V2 | V3 |
|---|---|---|
| WearGait-PD controls / Parkinson's (median per person) | 48 / 55 % | 89 / 87 % |
| CeTI / MHEALTH / PAMAP2 | 67 / 40 / 52 % | 98 / 100 / 83 % |
| Marpino / KneE-PAD (knee patients) | 32 / 36 % | 74 / 74 % |
| Caicedo older adults | 84 % | 84 % |

Sit-to-stand 82 %, stand-to-sit 84 %, bed transfer 99 % (simulation only).
Limits: sitting vs standing cannot be separated reliably at the tibia (together, "upright and still", 92-100 %);
seated knee extensions look like lying; stairs are weak on real people (up 40 %, down 53 %); walking with walker,
crutches or partial weight-bearing is not in the data yet.

## Use
```c
#include "kneil_tinyml.h"

static kneil_classifier_t clf;   /* 2.2 KB: keep static, not on a stack */
static kneil_metrics_t day;

void app_init(void) { kneil_classifier_init(&clf); kneil_metrics_reset(&day); }

/* call from a thread (not an ISR) with each sample in g, device frame */
void app_on_sample(float ax, float ay, float az)
{
	int cls = kneil_classifier_push(&clf, ax, ay, az);
	if (cls >= 0) kneil_metrics_update(&day, &clf, cls);   /* once per second */
}
/* after lost samples (FIFO overflow): kneil_classifier_init(&clf); never glue non-contiguous data */
```
`kneil_metrics_summary()` fills the 34-byte daily summary (minutes per class, sit/stand events, steps, cadence,
seated tilt). After a window, `clf.feat[]` holds the 20 features (for example `KF_MEAN_X..Z`, the window means in g).

## Zephyr / nRF Connect SDK
In this repository the application folder is itself the module (`list(APPEND ZEPHYR_EXTRA_MODULES ...)` in
`../CMakeLists.txt`). Kconfig: `CONFIG_KNEIL_TINYML=y`, `CONFIG_KNEIL_TINYML_FS_HZ=50` (the build stops if it differs
from the model's rate), `CONFIG_FPU=y`; optional `CONFIG_KNEIL_TINYML_MODEL_SMALL=y` (single tree),
`CONFIG_KNEIL_TINYML_SELFTEST=y` (test builds, about 35 KB of test vectors), `CONFIG_KNEIL_TINYML_SMOOTH`
(majority of 3 windows in the metrics, default y).

## Tests
- Host: `python tests/run_host_test.py` must print `HOST TEST: PASS (both models)`.
- Target: `kneil_selftest()`; pass = `n_feature_fail == 0` and `n_class_mismatch == 0`. On the nRF54L15 the
  features match the reference exactly; timing 0.6 ms mean, 1.0 ms max per window at 128 MHz.

## History
- v1 (synthetic data only): forest macro-F1 0.884 on unseen virtual patients; 65.7 KB flash.
- v1.1: optional input low-pass (`tools/train_kneil_tinyml.py --lowpass 6`; C and Python filters agree to
  5e-7 g); smoothed daily metrics (majority of 3 windows).
- V3 model (above).

## Retrain
CSV files with columns `time_s, acc_x_g, acc_y_g, acc_z_g, activity` at 100 Hz, device frame; see
`tools/train_kneil_tinyml.py --help`. After a new export, copy the 4 generated files to `include/` and `tests/`,
run the host test, then rebuild and run the on-board self-test.
