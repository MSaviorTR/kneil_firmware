# kneil_tinyml: on-device activity classifier and daily mobility metrics (v2.0, model V4)

C99 library, no dynamic memory, single-threaded per instance. It classifies a **4 s accelerometer window every
1 s** into 8 classes, applies the stairs rule, counts transition events and can add each result to a daily summary
(40 bytes, format 2) meant to be sent over BLE instead of raw data. In this repository it is used by the KNEIL live
firmware (`src/kneil_live.c`).

Classes: 0 walking, 1 stairs_up, 2 stairs_down, 3 **still** (sitting and standing together), 4 lying,
5 sit_to_stand, 6 stand_to_sit, 7 bed_transfer. The posture state (unknown / sitting / standing) comes from the
transition events and is carried next to the class.

Input: one sample at a time, in g, device frame **x anterior, y subject's left, z superior** (upright standing
gives about (0, 0, +1 g)), at **50 Hz** (the rate the model was trained for).

## v2.0 changes (17 Nov 2026, step E)
- **Window and hop come from the model**: `kneil_model_info.h` defines `KNEIL_MODEL_WIN_S 4` and
  `KNEIL_MODEL_HOP_S 1`; `KNEIL_WIN_N` / `KNEIL_HOP_N` are derived. The build stops with `#error` if those macros or
  `KNEIL_MODEL_N_CLASSES 8` are missing or inconsistent.
- **Stairs rule** (`kneil_stairs_rule`): a stairs window stays stairs only if the vote share of the predicted class is
  >= `KNEIL_MODEL_STAIRS_MIN_VOTE` (0.60), otherwise walking. `clf.proba[8]`, `clf.raw_class` and `clf.vote` keep the
  values before the rule; `kneil_classifier_push()` returns the class after it. With the single tree the
  probabilities are one-hot, so the rule never fires there.
- **Transition events (rule R1)**, counted once per event in `kneil_metrics`: a run of sit_to_stand / stand_to_sit
  windows (one other window between two of them keeps the run together) ends after 2 non-transition windows and is
  counted when a `still` window lies within 3 windows before the run or within 3 windows after its end; direction =
  majority of the run, tie -> first window. `bed_transfer` uses the same run rule without the still condition.
- **Posture state** splits the still minutes (sitting / standing / unknown). Assumption: a missed event puts the
  following still minutes in the wrong bucket.
- **Daily summary format 2, 40 bytes**: `format`, `n_classes`, `minutes_by_class[8]`, `minutes_sitting`,
  `minutes_standing`, `minutes_still_unknown`, `n_sit_to_stand`, `n_stand_to_sit`, `n_bed_transfer`,
  `sts_seconds_x10`, `steps`, `cadence_x10`, `stairs_cadence_x10`, `sit_tilt_x10`.
- **Measured size** (nRF54L15, `west build`, `rom_report`): forest build **386,664 B flash / 51,632 B RAM**,
  single-tree build **238,856 B / 51,632 B**; V3 was 409,668 B / 48,708 B. The classifier is 3,436 B (was about
  2.2 KB), the metrics 208 B, the summary 40 B. Host timing of one window (x86, `-O2`): 45-47 us.

## Model V4 (17 Nov 2026)
Folder `KNEIL_results/v4/tinyml_final_v4_lp6` of the training project (not in this repository). Forest of 20 trees
(15,822 nodes) plus a single tree (719 nodes), 20 features, 8 classes; trained on 50 Hz data filtered by a 6 Hz
low-pass, which the library applies on the chip. Training data: V4half (simulated implant-site data, Caicedo, the six
real implant-site datasets of V3 and the two new ones, Luo 2020 and Lencioni 2019, the latter two at half weight);
222,913 windows from 11 datasets, seed 0. Validation in the training project: 5-fold cross-validation by person.

| walking recognised (4 s, V4half) | median per person |
|---|---|
| WearGait-PD controls / Parkinson's | 84.9 / 85.2 % |
| CeTI / MHEALTH | 96.3 / 99.3 % |
| KneE-PAD / Marpino (knee patients) | 58.4 / 85.7 % |
| PAMAP2 | 84.9 % |
| Luo (new) / Lencioni (new) | 84.9 / 92.6 % |
| Caicedo older adults | 84 % (unchanged recipe) |

KneE-PAD stays the weak dataset (58 %); the stairs rule and the events are in `docs/STEP_D_SUMMARY.md` of the
training project. Limits unchanged: sitting and standing are not separable from the window alone (still + posture),
stairs remain weak on real people.

## Model V3 (16 Nov 2026)
Folder `KNEIL_results/tinyml_final_v3_lp6` of the training project (not in this repository). Forest of 20 trees
(18,900 nodes, about 192 KB of flash on the nRF54L15) plus a single small tree (1,117 nodes); 20 features,
9 classes; trained on 50 Hz data filtered by a 6 Hz low-pass, which the library applies on the chip.

Training data: simulated implant-site data (60 synthetic patients, 22 Camargo subjects replayed in the KNEIL
model), Caicedo older adults (virtual implant from markers), and real implant-site data of 265 people computed from
shank IMUs or motion suits (WearGait-PD, CeTI, PAMAP2, MHEALTH, KneE-PAD, Marpino; about 64 h).
Validation: 5-fold cross-validation **by person**.

| Walking recognised | V2 | V3 |
|---|---|---|
| WearGait-PD controls / Parkinson's (median per person) | 48 / 55 % | 89 / 87 % |
| CeTI / MHEALTH / PAMAP2 | 67 / 40 / 52 % | 98 / 100 / 83 % |
| Marpino / KneE-PAD (knee patients) | 32 / 36 % | 74 / 74 % |
| Caicedo older adults | 84 % | 84 % |

Sit-to-stand 82 %, stand-to-sit 84 %, bed transfer 99 % (simulation only).
Limits: sitting vs standing cannot be separated reliably at the tibia (together, "upright and still", 92-100 %);
seated knee extensions look like lying; stairs are weak on real people (up 40 %, down 53 %); walking with walker,
crutches or partial weight-bearing is not in the data yet.

## Use
```c
#include "kneil_tinyml.h"

static kneil_classifier_t clf;   /* v2.0: 3,436 B, keep static, not on a stack */
static kneil_metrics_t day;

void app_init(void) { kneil_classifier_init(&clf); kneil_metrics_reset(&day); }

/* call from a thread (not an ISR) with each sample in g, device frame */
void app_on_sample(float ax, float ay, float az)
{
	int cls = kneil_classifier_push(&clf, ax, ay, az);
	if (cls >= 0) kneil_metrics_update(&day, &clf, cls);   /* once per second */
}
/* after lost samples (FIFO overflow): kneil_classifier_init(&clf); never glue non-contiguous data */
```
`kneil_metrics_summary()` fills the 40-byte daily summary format 2 (minutes per class, the still minutes split by
posture, transition events, steps, cadences, seated tilt). After a window, `clf.feat[]` holds the 20 features, and
`clf.raw_class` / `clf.vote` / `clf.proba[]` hold the model output before the stairs rule.

## Zephyr / nRF Connect SDK
In this repository the application folder is itself the module (`list(APPEND ZEPHYR_EXTRA_MODULES ...)` in
`../CMakeLists.txt`). Kconfig: `CONFIG_KNEIL_TINYML=y`, `CONFIG_KNEIL_TINYML_FS_HZ=50` (the build stops if it differs
from the model's rate), `CONFIG_FPU=y`; optional `CONFIG_KNEIL_TINYML_MODEL_SMALL=y` (single tree),
`CONFIG_KNEIL_TINYML_SELFTEST=y` (test builds, about 40 KB of test vectors), `CONFIG_KNEIL_TINYML_SMOOTH`
(majority of 3 windows in the metrics, default y).

## Tests
- Host: `python tests/run_host_test.py` must print `HOST TEST: PASS (both models)`.
- Target: `kneil_selftest()`; pass = `n_feature_fail == 0` and `n_class_mismatch == 0`. The vectors are 4 s
  windows (16 vectors, 2 per class).

## Retrain
CSV files with columns `time_s, acc_x_g, acc_y_g, acc_z_g, activity` at 100 Hz, device frame; see
`tools/train_kneil_tinyml.py --help`. After a new export, copy the 4 generated files to `include/` and `tests/`,
run the host test, then rebuild and run the on-board self-test.
